# Практика интервью

## Что уже отработано

### 1. Самопрезентация
Есть рабочая версия: текущая роль — специалист, фактически выполняющий значительный набор задач системного аналитика; цель — перейти в классическую SA-роль с большим объёмом требований, интеграций и проработки решений.

### 2. Причина перехода
Ключевая мысль: сейчас часть высокоуровневой архитектуры сосредоточена у архитектора; хочется брать более крупные задачи и проходить полный цикл.

### 3. Выявление требований
На кейсе передачи данных между системами пользователь самостоятельно сформулировал вопросы про:
- место отображения;
- форму;
- назначение;
- дальнейшие действия пользователя;
- редактирование;
- экспорт;
- затрагиваемые процессы.

### 4. Если бизнес не знает поля
Показать текущий экран/ручной процесс, поговорить с фактическим исполнителем, определить реально используемые данные, затем совместно с разработчиком определить источник и способ передачи.

### 5. API
Отработано различие:
- API — интерфейс/контракт;
- REST — архитектурный стиль;
- SOAP — протокол;
- шина/брокер — инфраструктура сообщений;
- SQL — работа с БД.

### 6. Асинхронная обработка
Есть практический пример с очередью, статусами, ожиданием данных, перезапуском сервиса и повторной обработкой.

## Правило подготовки
Отвечать сначала своими словами и отталкиваться от реального опыта. После ответа — уточнять формулировку и только затем добавлять теорию.
