# Архитектурные основы

## DDD
Domain-Driven Design — подход к проектированию вокруг предметной области.

Для подготовки:
- bounded context;
- entity;
- value object;
- aggregate;
- domain service;
- ubiquitous language.

Главная идея для интервью: сложную предметную область полезно разделять на понятные контексты и отражать бизнес-модель в структуре решения.

## CQRS
Command Query Responsibility Segregation — разделение операций изменения состояния и чтения.

Command изменяет состояние.
Query получает данные.

Не означает автоматически наличие двух БД или двух микросервисов.

## Event-Driven Architecture
Система реагирует на события.

Пример:
OrderPaid → событие публикуется → несколько потребителей реагируют независимо.

Важно понимать:
- producer;
- event;
- broker;
- consumer;
- asynchronous processing;
- retries;
- duplicate delivery;
- idempotency.

## Связь с текущим опытом
Практический опыт с очередями и асинхронной обработкой уже позволяет обсуждать:
- статусы обработки;
- ожидание данных;
- остановку/перезапуск сервиса;
- повторную обработку;
- критические ошибки;
- блокировку сообщений;
- зависимость от внешних систем.

Kafka как конкретную технологию не следует выдавать за коммерческий опыт без фактической работы с ней.
